LESSON 00

First decide what job you want repeated.

n8n is useful when the same structured handoff happens again and again. It is not automatically useful just because several apps are involved.

Strong fit

  • A trigger is clear: form submitted, schedule reached, file added.
  • The inputs and outputs can be represented as fields.
  • The steps are mostly predictable.
  • A failed run can be inspected and retried.

Weak fit

  • The task is rare and faster to do once by hand.
  • Every case needs human judgment.
  • A mistake would send money or publish content with no review.
  • You cannot define what success looks like.
→

The right beginner target

Use a Manual Trigger, create a small JSON record, route it with an If node, and inspect every output. That teaches the engine without touching an external account.

LESSON 01

A workflow is a data pipeline.

The canvas is only the map. Every run moves one or more JSON items through connected nodes.

1Trigger

Starts the execution manually, on a schedule, or from an event.

→
2Transform

Renames, calculates, filters, or reshapes fields.

→
3Decide

Branches with If or Switch based on the current item.

→
4Act

Sends, creates, updates, or stores the result.

WORKFLOW

The whole process

A connected graph of nodes plus settings, credentials, and activation state.

NODE

One operation

A trigger, action, transform, condition, code step, or API call.

ITEM

One data unit

A JSON object—often one lead, message, row, task, or event.

EXPRESSION

A live reference

A value such as {{ $json.priority }} evaluated during the run.

EXECUTION

One complete run

The record of what ran, what each node received, and where it failed.

CREDENTIAL

Scoped access

An OAuth connection, API key, or account secret used by a node.

LESSON 02

Choose the least complicated route.

n8n’s official docs recommend Cloud for new users. Self-hosting gives more control, but you own updates, backups, security, and availability.

01

Install Docker Desktop with WSL 2

On Windows, the current one-line self-host setup runs inside WSL and uses Docker. Complete Docker’s own WSL setup first.

02

Open a WSL terminal

Use Ubuntu or another Linux distribution—not ordinary PowerShell—for the one-line command.

WSL · local install
$ curl -fsSL https://get.n8n.io | sh
03

Open the local editor

When setup finishes, use the local URL it reports. The standard local address is http://localhost:5678.

04

Keep it local while learning

Do not expose port 5678 to the public internet. A laptop session is ideal for training and prototypes, not 24/7 automation.

01

Create an n8n Cloud workspace

No local installation. n8n manages hosting, updates, and scaling. The official beginner quickstart uses Cloud and notes that a trial is available.

02

Start from scratch

Create a workflow, add a Manual Trigger, and follow Lesson 03. Do not connect real credentials until the no-credential flow works.

03

Review limits before building around it

Cloud plans differ by features and usage. Treat the current pricing page—not screenshots or old videos—as the source of truth.

01

Prototype locally first

A server makes a workflow available continuously; it does not make an untested workflow safer.

02

Use Docker Compose

The official hosting guide recommends Docker Compose for robust deployments with persistent data and additional services.

03

Add HTTPS, backups, updates, and monitoring

Production self-hosting means operating a service. If you do not want that responsibility, use Cloud.

!

Do not follow old npm tutorials blindly.

n8n’s current hosting docs say npm installation is deprecated from n8n 3.0. Prefer the official one-line setup or Docker Compose for a new self-hosted installation.

LESSON 04

Learn the item before adding apps.

Most beginner confusion is data confusion. A node does not “know” your intent; it receives structured input and produces structured output.

Item after Edit Fields
{
  "task": "Review weekly numbers",
  "priority": "high"
}

Use an expression when

  • The value comes from the current item.
  • The value changes on each execution.
  • You want to calculate from previous output.
  • You can verify the preview before running.

Use a fixed value when

  • The label or constant never changes.
  • You are creating test data.
  • The value is workflow configuration, not input.
  • You want the behavior to be obvious to a reviewer.
1:n

One input can become many items.

Always inspect item counts. A node that receives 100 items may run an action 100 times. Test with small, representative data before connecting any send, create, or delete operation.

LESSON 05

Graduate from toy flow to one real handoff.

Choose a workflow that saves repeated coordination without giving n8n irreversible authority.

Workflow picker

Choose the problem, not the fanciest integration.

STARTING PATTERN

Form → normalize → label → review

Capture structured input, clean the field names, assign a category, and stop for human review.

Form Trigger → Edit Fields → Switch → Review queue
CAPTURE

Intake router

Form submission → normalize fields → label urgency → write a draft row.

DIGEST

Daily brief

Schedule → fetch records → summarize deterministically → save a draft.

ROUTE

Follow-up sorter

New item → validate required fields → branch by state → create next-step task.

SYNC

Two-system bridge

New record → map fields → search destination → create or update.

WATCH

Exception monitor

Schedule → check source → filter only exceptions → notify one reviewer.

AI

Bounded classifier

Input → redact → classify → validate schema → send uncertain cases to review.

Before activation

  • Test the happy path and a missing-field case.
  • Confirm how reruns avoid duplicates.
  • Add an explicit error path.
  • Know how to deactivate it quickly.

Never hard-code

  • Passwords or API keys inside expressions.
  • Secrets inside a Code node.
  • Production credentials in exported workflow JSON.
  • More account scope than the node needs.
LESSON 07

Debug the first red node, not the whole canvas.

Open the failed execution, select the first node with an error, then inspect its input, parameters, and error message.

Nothing runs when the event happens

Manual tests and production triggers are different. Confirm the workflow is active and that the node is using its production trigger or webhook URL.

An expression returns undefined

Run the upstream node, inspect its JSON, and verify the exact field path and capitalization. Expressions only see data available in that execution context.

The next node runs once per record

That is the item model working as designed. Check the incoming item count. Aggregate, limit, or loop deliberately before a costly or external action.

A workflow creates duplicates

A retry repeated a non-idempotent action. Add a stable external ID, search before create, or store a processed marker. Test the same input twice.

Local n8n stops when the laptop sleeps

A local process is not an always-on service. Keep local for learning; move a proven workflow to n8n Cloud or an operated server when it must run continuously.

An old tutorial says to install with npm

Check the official hosting guide. It currently says npm installation is deprecated from n8n 3.0 and points new self-hosted users toward one-line setup or Docker Compose.
