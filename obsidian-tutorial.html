Obsidian is useful when today’s note should make a future note easier: research, coursework, case files, recurring decisions, and long projects. It is overkill for a grocery list or a pile of notes you never revisit.

Best fit: a durable, private reference system.

The core advantage is not the graph. It is that a vault is a normal local folder of Markdown files, while Obsidian adds links, backlinks, properties, search, templates, and multiple views over those files.

Use it

You revisit the same topics, need source trails, and want files you can still read outside the app.

Trial it first

LESSON 01

Know what each layer does.

Obsidian is an editor and index over files. The files remain the source of truth. Links and properties create structure; AI is optional.

VAULT

A local folder

One directory containing notes, attachments, and an .obsidian configuration folder.

NOTE

A Markdown file

Plain text with an .md extension. Readable without Obsidian and editable with other text tools.

LINK

A deliberate connection

[[Topic]] points to another note. Backlinks show every note that points back.

PROPERTY

Structured metadata

Small fields such as type, status, source, date, or ticker stored at the top of a note.

VIEW

A lens, not new data

Search, graph, and database-style views reveal patterns already present in notes and properties.

AI

A guest analyst

A model can summarize selected material. It should not silently become the owner of your vault or its truth.

NOTE 01 · SOURCECompany filing

Facts, dates, excerpt, original URL.

NOTE 02 · THESISInvestment thesis

Claims linked back to the source note.

NOTE 03 · DECISIONPost-mortem

What changed, what held, and what to revisit.

LESSON 02

Create one vault, not a taxonomy.

The first build should take fifteen minutes. Use a broad vault name, four folders, and one index note. Organization follows actual use.

01

Install from the official site

Download Obsidian for Windows, install it normally, and choose Create new vault. A vault is just a folder, so put it somewhere easy to back up.

02

Use Knowledge, not Obsidian experiment September. Do not create separate work, school, market, and life vaults until a real security or ownership boundary requires it.

LESSON 03

Write notes that can survive retrieval.

A good note has one clear subject, a source or provenance line when facts matter, and links that explain why it belongs in the system.

What you type

Markdown
---
type: research
status: active
source: "[SOURCE URL]"
---

# Margin policy change

## Claim
The broker changed the rate.

## Evidence
See [[September statement]].

## Related
- [[Broker dispute chronology]]
- [[Cash-flow constraints]]

What the structure means

1
Properties filter the note.
Type and status support future views.
2
The title names one subject.
Not “random thoughts 7.”
3
Claims point to evidence.
The statement note preserves the source trail.
4
Links state relationships.
See the use-case patterns.
CClaim

What this note says in one sentence.

LLinks

Which existing ideas this changes or supports.

EEvidence

The source, date, excerpt, or record behind it.

AAction

What decision or next step follows, if any.

RReview

When this could become stale or needs checking.

∴

The CS50 rule: build the smallest useful abstraction.

Do not invent twenty note types before you have twenty notes. Start with source, concept, project, and decision. Add a type only when two real notes need the same structure.

LESSON 04

Four workflows worth testing.

Each one turns repeated work into linked evidence. Open a pattern and copy the starter note.

Market research packetsources → thesis

Give each company one hub note. Link filings, earnings notes, thesis changes, and decision reviews back to it. Keep live prices out; Obsidian is the research memory, not the tape.

Company hub template
---
type: company
ticker: [TICKER]
status: watch
---

# [Company]

## Thesis in one paragraph
[Current thesis]

## Primary evidence
- [[Latest 10-K]]
- [[Latest earnings notes]]

## What would change my mind
- [Falsifier]

## Decisions
- [[Decision — YYYY-MM-DD]]
Coursework concept networklearning

One note per durable concept, not per lecture. A lecture note can link to concepts such as elasticity, agency costs, or contribution margin.

Concept note
---
type: concept
course: [COURSE]
status: learning
---

# [Concept]

## In my own words
[Explanation]

## Example
[Business example]

## Confused with
- [[Related concept]]

## Source
- [[Lecture — YYYY-MM-DD]]
Dispute or case chronologyevidence

Keep one chronology hub and one note per primary document. Link every consequential claim to the document that establishes it; do not bury exhibits in a giant narrative.

Event note
---
type: event
date: YYYY-MM-DD
matter: [[Matter name]]
source: [[Exhibit label]]
---

# YYYY-MM-DD — [Event]

## Established
[What the record directly shows]

## Contested
[What another party disputes]

## Significance
[Why it matters]

## Follow-up
[Missing proof or next step]
Weekly decision reviewreflection

Capture only decisions and lessons that will matter again. A short weekly review is more valuable than daily notes no one reads.

Weekly review

- [Observation] → [[Source note]]

LESSON 06

            
Climb the AI ladder one rung at a time.
The video’s AI layers make sense only after retrieval works without AI. Begin with manual, inspectable context and keep inference local.

          

          

            
LEVEL 0
Human vault
Notes, links, properties, search, and templates. This is already a complete useful system.

            
LEVEL 1
Selected-note AI
Copy one note or small packet into local Hermes. Ask for a summary, critique, or missing links.

            
LEVEL 2
Structured index
Use consistent properties and saved searches or Bases-style views to create a database over your notes.

            
LEVEL 3
Local retrieval
Only later, add a reviewed local tool that selects relevant notes for your local model. Keep it read-only first.

          

          

            
01
Use Hermes as a reviewer, not a vault owner
Paste into local Hermes with selected notes
You are reviewing a small Obsidian source packet. Use only the notes below.

Return:
1. The central claim
2. Direct supporting evidence, cited by note title
3. Contradictions or stale dates
4. Missing links to other concepts named in the packet
5. A proposed index-note outline

Rules: Do not invent notes, sources, dates, or facts. If the packet does not establish something, write “not established.”

NOTES:
[PASTE THE SELECTED NOTES]

            
02
Add one core feature at a time
Enable built-in Templates after you repeat a note structure. Add Properties when you need filtering. Use Graph only to inspect connection gaps—not as a dashboard you must keep pretty.

            
03
Back up before automation
A local vault protects you from platform lock-in, not from disk failure or accidental deletion. Keep an independent backup before scripts or plugins get write access.
PowerShell · manual local backup example
robocopy "C:\Path\To\Knowledge" "E:\Backups\Knowledge" /MIR /XD .trash
Replace both paths first. /MIR mirrors deletions too, so test with a disposable folder before relying on it.

          

          
$
What this course deliberately skips
Obsidian Sync, Publish, paid AI APIs, hosted vector databases, affiliate templates, and “second brain” courses. None are needed to prove whether the core workflow is useful to you.

        

      


      

        

          

            
LESSON 07

            
Local files are a boundary, not a force field.
Obsidian stores notes locally, but anything you install, sync, paste, or automate can expand the trust boundary. Keep the core simple until you understand the permissions.

Safe starting boundary
  • Keep Restricted Mode on and use only core plugins.
  • Back up the vault outside its working drive.
  • Paste only selected, redacted notes into Hermes.
  • Give any future automation read-only access first.

            
Never store in ordinary notes
  • Passwords, API keys, recovery codes, or private keys.
  • Full account, claim, policy, or government ID numbers.
  • Unredacted client records without explicit authorization.
  • A single copy of anything you cannot afford to lose.
